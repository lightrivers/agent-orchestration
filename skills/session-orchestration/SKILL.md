# 主会话规则

本文中 `$SKILL` 指本 skill 所在目录。子代理（runner）的细节用 `subagent-dispatch` skill。会话工具（`start_session`、`SendMessage`、`detach_session`、`get_usage` 等）是 Claude Desktop Code 页的工具；在 CLI 里用时，把"子会话"换成另开的终端会话，回报改成写文件。

项目文件约定（`install.sh --project-only <目录>` 会生成空模板）。项目 `CLAUDE.md` 里写了不同的文件名时，以 `CLAUDE.md` 为准，本 skill 和下属文档里的文件名都按它替换：

| 文件 | 用途 | 谁改 |
|---|---|---|
| `outputs/状态.md` | 当前状态、排队、会话分工、规则、已定决策 | "规则""已定决策"只由主会话改；其余整理员更新 |
| `outputs/用户待办.md` | 所有要用户做或决定的事 | 主会话 |
| `outputs/_收件箱.md` | 各会话一行式回报 | 所有会话只追加 |
| `outputs/_索引.md` | outputs 下每个文件的用途和是否现行 | 整理员 |
| `work/当前主会话.md` | 当前主会话的 `local_…` id | 换届时改 |
| `work/主会话_交接.md` | 交接便签 | 主会话 |
| `work/评审_待审.md` | 不紧急、等集中评审的风险 | 所有会话 |
| `work/杂项待办.md` | 与当前任务无关的新需求 | 所有会话 |

## 分工

- 主会话：和用户沟通、定方案、写任务书、验收、做决定、执行 L3。不自己扫描、写常规脚本、读大段日志。
- DeepSeek：默认执行者。子代理（runner）做一次性任务；DeepSeek 模型的 Desktop 子会话做多轮工作和陪用户在界面上操作（启动方法见 `subagent-dispatch` skill 的 `reference/desktop-session.md`）。
- 评审模型（另一家的强模型）：费用高的话过程中不拉起。不紧急的风险记 `work/评审_待审.md`，新方案执行前或全部完成后一次审。紧急风险（丢数据、暴露公网、让在跑的任务失败）当场处理，事后补记。
- Claude 子会话默认用主会话的模型，换渠道由用户决定。

## 派活顺序

1. 1–2 条命令 → 自己做。能用只读命令查到的信息自己查，不让用户去界面看。
2. L3 → 准备命令和回滚方案，进用户待办，确认后自己执行。
3. 边界清楚 → DeepSeek。
4. 同领域、现有会话还在做 → `SendMessage` 追加。
5. 能独立交付的事 → 新会话（一个会话 = 一个交付物）。

等依赖的任务记进状态文件"排队"，等的时候让 DeepSeek 做下一阶段的只读准备。前一个会话完成后由它直接通知下一个（`SendMessage`），不要靠用户转达。

主动拆分：收子会话检查点时顺手判断它是否太重（范围横跨多件独立的事、上下文涨得快、回报里堆了多个待决定项）。能独立交付的一块就拆成新子会话。拆前先把相关事实整理成一份自包含的任务书（`work/<任务>_任务书.md`），新子会话只读它和 `$SKILL/sub-session.md`，不用读一堆历史文档。

## 风险级别

- L0 只读、L1 可回滚小改动、L2 影响面大但能恢复：DeepSeek 在任务范围内直接做，先备份，每次写操作记 `changes.md`。主会话在任务结束时审 `changes.md`。
- L3：格式化、删数据、清回收站、动 RAID/存储池/快照、覆盖备份、改账号密码/2FA、对公网开端口、轮换或删除密钥、不可回滚的生产变更，以及项目 `CLAUDE.md` "L3 补充"列出的操作。只由主会话在用户确认后执行。
- 改动真实环境的任务书套用 `subagent-dispatch` skill 的 `templates/task-brief.md`。

## 并发

Claude 会话 3–4 个同时工作通常正常，DeepSeek 不限。同一渠道 5 分钟内 3 次以上 503/429 就停开新会话，报告用户，不自动换渠道。

## 用户

- 只有主会话找用户。所有要用户做或决定的事进 `outputs/用户待办.md`，在同步点一次给。做完、验证过的项随时删掉。
- 用户不在时（长任务、夜里）自己推进，能决定的就决定，攒一份清单等用户回来一次问。
- 能改回来的选择按建议直接做，事后告诉用户。
- 用户只做：物理操作、要他账号密码的操作、偏好、L3 确认。能用命令行做的不写成用户操作。

## 监督 DeepSeek

按停点收检查点（≤1 KB），不读它的聊天记录。先用 `subagent-dispatch` skill 的 `scripts/check_progress.py` 扫 `progress.md` / `changes.md`，报警时立即看。DeepSeek 的根因判断复核后才能据此改东西。

## 文档

- 子会话自由写文档，只往 `outputs/_收件箱.md` 追加一行式条目。
- 同步点、换届前或收件箱超过约 30 条时，派 DeepSeek 子代理按 `$SKILL/organizer-brief.md` 整理，主会话只审状态文件 diff。
- 新会话启动只读 `outputs/_索引.md`、状态文件、交接便签。

## 上下文和换届

- 每轮调用 `wrap_up` 前调一次 `get_usage`（纯聊天轮除外）。`tokensUsed` 超过 20 万时，在 wrap_up 里问用户是否换届。
- 用户说"换届"/"交接"，或要离开较长时间（回来时缓存已冷），或自己出现不看指令、重复已做的事等症状：读 `$SKILL/handover.md` 照做。
- 每个同步点更新 `work/主会话_交接.md`；用户新给的约束当场写进它的"已定决策 / 不要做"。
- 子会话不自动换届，用户手动说。

## 派子会话

给子会话的任务书里贴上 `$SKILL/sub-session.md` 的内容（或写"先读 <该文件的绝对路径>"），再写本次任务的目标、范围、允许级别、交付物。

## 归档

交付物、回报、遗留都落盘就归档。等用户马上回来的测试且之后还要它执行的，可暂留。
