# Claude CLI：高级评审

- 定位：在实施前独立评审重要方案，挑战关键假设、找反例和边界漏洞。不做常规 worker 工作，主代理负责采纳判断和实施。
- 何时调用（满足即可调用，不需要逐次询问）：关键架构或算法有多种合理选择；重要结论依赖多个假设或证据冲突；失败代价高或难以回滚的决策；难题经过主代理的实质分析仍未解决。
- 不要用于：代码搜索、资料汇总、机械改写、常规测试，以及没有新证据的重复复核。
- 模型默认 `claude-opus-5-5` / `medium`（`--model` / `--effort` 可改，改前先和用户讨论），不要用 `opus` 这类别名。主代理本身是同一模型时属于同模型复核，报告中要标明。
- 轮次：每个用户任务默认一轮。runner 默认不设费用上限；需要时可用 `--max-budget-usd` 设 CLI 估算的停止阈值（不是中转站账单上限）。
- 限制：默认总超时 600 秒、连续 300 秒无输出判为卡住、最多 6 个内部工具轮次（不是 6 轮评审）。不能靠放大超时、轮次或拆小任务绕过一轮评审的默认规则。
- 先讨论再调用：第二轮或续审、并行或批量评审、改模型或推理强度、扩大工具权限。
- 证据：默认无工具，只分析任务文件里的内容。需要读文件时用 `--tools Read,Glob,Grep`，`--cwd` 指向只放脱敏副本的专用目录，不要指向仓库根目录或家目录；目录里不放 `.env`、密钥、未筛选的日志或符号链接。CLI 升级后先用无敏感内容的哨兵文件重新验证只读边界，验证前只用无工具模式。
- 目的地：runner 读取 `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL`（进程环境变量优先），即用户当前选中的中转站或官方 API。只校验 URL 是 HTTPS、不含凭据、查询或片段，且未启用 Bedrock/Vertex/Foundry 路由；实际主机记在 `request.json` 的 `api_host`。只发送裁剪、脱敏后的方案、代码和证据。
- 评审方式：独立推导时只给问题和原始证据，不先给主代理的结论；审查方案时要求找替代解释、失败条件和能证伪的测试。输出建议用 JSON：`verdict`（support/revise/inconclusive）、`findings`、`counterexamples`、`suggested_tests`、`uncertainties`。不要用顶层 `ok=false` 表达反对意见，runner 会把它判为交付失败。
- 主代理逐项核实评审意见，说明采纳或不采纳的原因。两个模型意见相同不等于证明。
- 完成条件：最后一个 `result` 为 `subtype=success`、`is_error=false`，且有非空结果或结构化输出。模型报告与请求不一致、出现意外工具或 MCP、开启 fast mode 时，runner 判交付失败，不要自动换模型或重跑。CLI 没有报告的字段（模型、工具、费用）要由主代理核实，不能把字段缺失当作已验证。
- runner 只传单次命令参数，不改用户全局默认模型或推理强度。
