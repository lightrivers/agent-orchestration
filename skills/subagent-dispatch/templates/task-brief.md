# 改动真实环境的任务书模板

主代理给 DeepSeek（runner 或 Desktop 子会话）派会碰服务器、配置、外部系统的任务时，复制下面的结构，删掉用不到的部分。runner 把它存为 `work/tasks/<任务>.txt`；Desktop 子会话直接 `SendMessage` 发送。纯本地、只改仓库文件的任务不需要这么重，按 SKILL.md 的"任务书要求"写即可。

```
目标：<一句话，完成后应看到什么>
背景与已确认事实：<只写需要的；文件路径代替长段落>
范围：主机 <…>；可动的服务/目录 <…>；范围外不碰。
允许级别：L0–L2（或更窄）。遇到 L3 停下写检查点。
  L0 只读；L1 可回滚的小改动；L2 影响面大但能恢复。
  L3 = 格式化、删数据、清回收站、动 RAID/存储池/快照、覆盖备份、改账号密码/2FA、对公网开端口、轮换或删除密钥、
       不可回滚的生产变更，以及项目 CLAUDE.md "L3 补充"列出的操作。
连接：只用项目约定的连接脚本或已建立的主连接。不要在任何文件里写密码、密钥、cookie。
步骤：
  阶段 1：<…>  预期：<可核对的数字或状态>
  阶段 2：<…>  预期：<…>
默认决定：<路径不存在就跳过并记录；输出过长只留前 50 行；……>
  不在这里的问题，按最保守、能回滚的做法做，并在检查点写明。

工作目录：work/<任务>/，写三个文件：
  progress.md   每条命令追加一行：时间 | L0–L3 | 命令 | 目的 | 结果一句话
  changes.md    每次写操作一行：时间 | 级别 | 主机 | 改了什么 | 改前值或备份路径 | 改后值 | 怎么回滚
                改配置文件前先复制成 <原文件>.bak-<时间>；没有文件的设置先导出当前值。
  checkpoint.md 停点时写（≤1 KB）：停在哪个停点、做了什么、看到的原始数字、下一步打算、需要谁决定什么。

停点（遇到就写检查点，然后停下）：
  1. 每个阶段结束。
  2. 要执行范围外或 L3 的命令。
  3. 命令退出码非零，或结果和"预期"不符。不要自行补救。
  4. 想写"原因是……""确认是……"。改写成：假设 + 支持证据 + 反证或没查的项。
  5. 同一个问题已经试了 2 种办法。
停点以外不要提问。

[Desktop 子会话加这一行] 写完检查点后读 work/当前主会话.md 取主会话 id，用 SendMessage 发一句"<任务> 到停点 N，见 work/<任务>/checkpoint.md"，等回复。
[runner 加这一行] 到停点就结束本次运行，最后一句回复检查点路径。

交付：最后回复一行：结论 + 文件路径。
```

主代理收到检查点后，先跑 `python3 $SKILL/scripts/check_progress.py work/<任务>` 扫 `progress.md` / `changes.md`，有报警立即看；不读它的聊天记录。子代理的根因判断复核后才能据此改东西。
